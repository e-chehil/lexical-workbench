## 1. 设计原则（全局判准，实施中所有取舍以此裁决）

- **P1 名录即舞台**：结果表是 Explore 的主角，占据最大连续空间；导航、筛选、详情、汇总都按需展开或浮在页缘。禁止退回「多个固定列先占空间、表格吃剩余」的结构（现有 224+256+420 的教训）。
- **P2 双墨纪律**：数据的声音必须可见且稳定，且**不得只靠颜色区分**：官方墨（源数据）用确定字重与正式声调；计算铅笔（（计算）派生）带文字后缀 + 降一档灰墨 + 常规字重；空白注记（null=未收录）显示「—」＋明确来源文字说明，绝不看起来像 0；个人墨（学习状态与词集）是交互层专用声（带文字标签）。任何数字的来源身份在一屏内可辨认（颜色、字重、位置、文字四重编码），不依赖悬停。
- **P3 单位自述**：当前查询单位、生效条件、集合来历与上限必须自解释：查询条为「一句话自述」；不适用条件禁用并给原因，而不是静默丢弃或算出 0；投影是显式两步（预飞说明 + 成票），上限与取样规则在事前可见。
- **P4 一笔可撤**：每个批量写入是一「笔」：目标对象、数量、跳过项与批次号对用户可见，撤销常驻可点；聚合不可标记的原因就地说明（行内常态，不是对话框）。
- **P5 渐进而完整**：渐进披露只能折叠说明性复杂度，不能隐藏专业能力；任何被折叠的能力都在一跳内可达且在 URL 中保真。
- **P6 语义跨断点**：桌面与移动是同一语义的两种组织；例外信息（多词族、未收录、多词性、官方/计算差异）在窄屏折叠为注记但**不消失**；可触达性（键盘、触屏、读屏）是同一功能语义的三个入口。

## 4. 关键交互与页面状态

### 4.1 查询语义（P3 的落地）

- **投影集合 ≠ 已保存的静态词集（用户提醒后修订）**：投影产生的是引擎查询内的一次性 `in_refs` 固定结果集；「静态词集」是用户在存储层显式保存的 Collection。两者实现不同、用途不同：票据只描述前者（来源、上限、取样），不声称它已被保存；把投影结果存为词集是另一个显式动作（沿用 T05 的「加入词集」）。所有「已定格」措辞改为「投影集合（in_refs）」类中性表述，避免暗示已持久化。

- **查询条一句话自述**（左→右）：`类型 · 总数/库内总量 · 条件芯片… · 集合性质`。例：`COCA 词性条目 · 1,000/60,000 · 官方排名 ≤1000`；投影后：`词形 · 898/94,954 · ⟐静态词集（源自 1,000 条词性记录）`。
- **条件芯片**：官方/计算指标芯片自带「（计算）」声；每个芯片可单独移除（×）。
- **类型切换适用性策略（替代现「静默丢弃」；URL/契约变更，实施前已向用户报告）**：切到新 kind 时，新 kind 无法满足的条件**保留在芯片条中但转为禁用态 + 原因**（例：「官方排名仅适用于 COCA 词性条目」），`LexQuery` 不含它（查询正确性不变）；切回原 kind 时自动恢复生效。因此 **URL 只承载适用条件，禁用条件只存在于会话态**（刷新后消失，与旧行为的丢失程度相当，但会话内不再静默丢失）。这是 `filterState.ts` 的 UI 状态契约变更，需新增测试；引擎协议不动。详情泊靠偏好存 localStorage（不进 URL，非查询语义）。
- **投影票据两步流（替代事后弹消息）**：
  1. 预飞面板（点「投影」时）：声明源集合（类型+总数）、目标类型、取样规则（**按当前排序取前段，≤5,000 上限**）、预计数量；按钮 = `投影并定格` / 取消。
  2. 成票：票据带常驻表头上方：`◈ 投影集合（in_refs）· 1,000 条 COCA 词性记录 → 898 个词头 · 按官方频次取前段 · [返回源查询]`；总数字段同时显示 `898（上限 5,000）`；票据即 `in_refs` 查询的可见身份（来源/上限不因导航丢失——来源说明存于会话态即可，丢失时降级为「投影集合（来源未记录，可重新投影）」）；如需长期保留，走显式的「加入词集」动作存入存储层静态词集。
  3. 「返回源查询」= 单步恢复投影前的动态查询（会话态 + history tuple 双保险）。
- **聚合摘要**与总数并列常显（现有 aggregate chips 语义保留，换皮为名录注记样式）；空结果区分「真 0 条」与「条件不适用致 0」：后者空态给出病因与两条出路（`[切换到 COCA 词性条目]` `[移除该条件]`）。

### 4.2 选择、焦点与批量（P4 的落地）

- 键盘模型完全保留：↑↓ 移动、Shift+↑↓ 区间、Space 勾选、Enter 开详情、1–5 设状态（选择优先，否则焦点行）、Esc 关闭浮层/抽屉。焦点行有恒定可见的焦点环；选择集计数在批量条与顶栏可见。

## 5. 视觉语言与信息层级

### 5.1 色彩策略（Restrained——中性纸面 + 一个结构主色 + 官方红特权用途）

- 光明主题：纸面 `--paper`（冷白 ≈#FAFAF9）、面板纯白、正文墨 `--ink`（≈#1B2432）、结构主色**靛蓝 ≈#3B5BDB**（交互、焦点、选择、链接）、**官方红 ≈#B03A2E**（只用于：官方位次签、CET 级标、错误、「官方」出处强调——禁止用于普通强调）。
- 五态学习色（全部配文字标签）：未评=灰 / 待学=蓝 / 在学=琥珀 / 掌握=绿 / 暂缓=紫。个人墨的另一层：操作回执与批次 用柔和「笔迹蓝」底（克制，不做手写字体）。
- 暗色主题：藏青调深纸面（≈#0E1526 系），同一角色映射；官方红与五态需单独校对比度。
- 明确**不用**：大面积灰蓝渐层、胶囊 pill 泛滥、卡片阴影堆叠、装饰性动效。（组件语言：1px 细线（hairline）分域、2–4px 微圆角、平面、表格优先于卡片。）

### 5.2 字体（全部自托管，修复现 Google Fonts 外链；兼顾中/英/数字与 PWA 离线）

- 词头/展示 = **Source Serif 4**（Latin 子集 WOFF2，经 @fontsource 本地依赖打包进 dist，离线可用）——词头永远是拉丁词；中文界面正文 = 系统黑体栈（PingFang SC/微软雅黑…，第一阶段不做 CJK 网络字体：体积大且缺字回退风险高，中文层级靠字重与字距表达）；数字/引用/ref = **JetBrains Mono**（等宽 + tabular，@fontsource 本地打包）。
- 中英文数字混排规则：CJK 文本不与衬线混排行内基线；数字列一律等宽字轨对齐；词头（拉丁）与中文标签之间用间距分层，不用字体对比硬拗。
- 删除 index.html 的 Google Fonts preconnect/link（离线一致性 + 不向第三方发请求）；`src/index.css` 中失效的 Inter/Source Serif 4 引用一并修正为实际加载的字体。

### 5.3 字阶与层级

- 名录行高 44–48px：词头 15–16px/600（衬线）；首列锚数值 13px mono；常规 UI 文本 12–13px；功能文本下限 11px（修复 10px 层级塌缩）；词条页（详情）词头 34–40px 衬线、来源块标题小号加字距。
- 行内四声层级（从左到右）：**首列锚** → 词头+内联徽记 → 指标列（列头带来源徽记，单元格不重复来源小字）→ 例外注记 → 个人状态。
- `null`：显示 `—`＋脚注符，悬停/点开 = `<source> 未收录（非零可能）`；`0` 显示 `0` 并带「源数据为 0」说明（沿用 metrics.ts missing 文案）。
